# 프로젝트 공용 메모리

팀원과 AI가 작업을 시작할 때 참고하는 문서예요. 제품과 베타 범위의 합의, 현재 구현, 검토 중인 안을 한곳에서 확인할 수 있어요.

## 제품 방향

- 올해 우리는 사진으로 한 해를 돌아보는 연말 회고 앱이에요. 공통 홈에서 회고 기능을 고르고, 결과는 내 회고에서 다시 열 수 있게 설계해요.
- 잇기는 첫 번째 기능이에요. 친구가 서로의 사진첩에 남긴 같은 순간을 찾아, 서로 다른 시선으로 찍은 사진을 함께 보여 줘요.
- AI와 데이터 분석은 같은 순간을 찾는 데 쓰여요. 시간 기준으로 후보를 좁히고, 이미지 비교를 더했을 때 실제로 결과가 나아지는지 확인하는 실험을 계획했어요.
- 프런트는 겨울 창가와 두 친구를 픽셀아트로 표현해요. 후보 비교 화면과 회고 카드에서는 사진이 잘 보이도록 여백과 간결한 문구를 사용해요.

## 잇기 첫 베타 설계

1. 친구 한 명을 초대하고 각자 사진 10~20장을 골라요.
2. 분석에 동의한 사진을 제출해요. 지금 API 초안은 두 번째 제출이 끝날 때 서버에서 작업을 한 번 시작하고, 축소본과 촬영 시각을 비교하는 흐름이에요.
3. 같이 보낸 순간으로 보이는 후보를 검토해요. 각자가 공개할 자기 사진을 승인하고 나면 후보에서 두 사람의 사진을 함께 볼 수 있어요. 공개 전 응답에는 친구의 사진 ID와 미리보기 경로가 들어가지 않아요.
4. 두 사람 모두 같은 순간이라고 확인한 후보를 공동 회고에 담아요. 후보가 비거나 답이 다르면 사진을 다시 고를 수 있어요.

대기, 분석 중, 후보 없음, 분석 실패는 각기 다른 상태예요. 화면이 이 상태들을 어떻게 구분하는지는 [잇기 API 계약 초안](linking-api.md)에서 확인해요. 서버의 경로와 응답 필드는 연동 작업에서 확정해요.

프런트의 초대, 분석, 친구의 응답은 예시 데이터로 동작해요. 실제 친구 참여, 기기 사진 접근, 서버 연결과 회고 저장은 연동할 작업이에요. 팀원이 웹앱에서 처음 막히는 단계, 잘못 연결된 장면, 회고를 친구에게 보내고 싶은지를 보고 수정한 뒤 다시 확인해요.

CV 실험은 직접 찍어 실제 사용 조건을 재현한 사진과, 기존 데이터셋에서 골라 평가용으로 구성한 샘플을 구분해 기록해요. 같은 모임을 다른 각도에서 찍은 경우, 같은 장소를 다른 날 찍은 경우, 겹치는 순간이 없는 경우를 공통 샘플에 넣어서 시간 기준선과 이미지 비교 결과를 비교하는 방향이에요.

## 검토 중인 결정

- 개인 회고 기능은 아이디어 검토 중이에요. 활동 기록에서 한 해의 과정을 발견하는 방향이 있으며, 범위와 우선순위는 팀 논의가 필요해요.
- 공개 데이터셋, 촬영 규모, MegaLoc을 포함한 모델 후보와 평가 기준은 검증 뒤 결정해요.
- 참여 세션 전달, 분석 실패 재시도, 사진 보관과 삭제 기준은 실제 서버를 붙이기 전에 정해요.
- Safari 실기기, 첫 웹 배포, 두 기기 참여와 외부 테스터 피드백은 결과가 확인되면 이 문서와 작업 카드에 기록해요.
